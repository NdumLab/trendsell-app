## 2. Release change summary

The production-to-candidate range is `90d6312..150d118`: 51 files changed, 1,665
insertions and 159 deletions. It contains commits `695c0fb` and `150d118`.

### Controlled-pilot and operational hardening

- Makes `controlled_pilot` an enforced production release tier and refuses public
  registration in that tier.
- Hardens the systemd service template and adds a six-hour backup freshness/integrity
  checker for the existing daily local/S3 backup.
- Adds server-side invitation limits and controlled production smoke coverage.
- Does not add billing, public registration, external monitoring notifications or a public
  launch path.

### Evidence and product investigation

- Adds an optional server-side Amazon Creators API `GetItems` adapter with bounded timeout,
  safe failure handling, response hashing, parser/collector versions, workspace-scoped
  source health and immutable catalog snapshots.
- The adapter defaults to disabled and the installed production configuration resolves to
  `amazon_creators_enabled: false` with no provider credential or rights approval.
- Expands the evidence method to `evidence-quality/1.1.0`, including advertising and
  creator categories while keeping user-entered observations labelled `User input` and
  capped below the GO threshold.
- Adds product-level advertising, creator, search and marketplace sections with explicit
  association-versus-attribution and missing-data copy.
- Changes workspace export to `trendsell-workspace-export/3` so permitted source snapshots
  and source-health records can be retained with the workspace.

### Quotes and decisions

- Preserves supplier quote amount and original currency rather than assuming USD.
- Allows a dated quote to populate a decision through an explicit user-provided conversion
  rate and snapshots the quote plus conversion in the immutable assessment.
- Updates decision-gate copy to `decision-gates/1.2.0` so margins that deduct allocated
  fixed and launch costs are not mislabeled contribution margin. Numeric thresholds and
  formulas do not change; old threshold versions remain replayable.

### Loading and workflow verification

- Adds controlled browser timing for fresh guest, authenticated bootstrap and client-side
  navigation, plus quote-to-decision and sales-driver browser coverage.

## 8. Proposed rollback and stop thresholds — pending approval

These are conservative controlled-pilot proposals, not approved SLOs:

| Signal | Proposed stop/rollback condition |
| --- | --- |
| Data and tenancy | Immediate rollback/containment on any confirmed cross-workspace access, authorization bypass, lost/rewritten record, decision replay mismatch, export omission or credential exposure |
| Schema/readiness | Stop before restart on any unexpected migration/DDL; rollback after two consecutive non-200 `/api/ready` results 30 seconds apart |
| Critical smoke | Roll back on failure of owner authentication, expected reviewer/viewer denial, quote-backed decision save/reload, or export reconciliation |
| Server errors | Roll back on three release-related 5xx responses in five minutes at low volume, or more than 2% 5xx over any five-minute window containing at least 50 requests |
| Latency | Investigate immediately and roll back if authenticated API p95 exceeds 2 seconds for ten minutes over at least 20 requests, or health/readiness p95 exceeds 1/2 seconds respectively |
| Process stability | Roll back on two unexpected TrendSell service restarts in ten minutes or failure to remain active for five minutes after restart |
| Resource saturation | Stop/rollback if service memory exceeds 512 MiB for ten minutes, host available memory falls below 1 GiB, disk exceeds 85%, or PostgreSQL connections exceed 80% of its configured maximum for ten minutes |
| Security delivery | Roll back if HTTPS redirect, HSTS/CSP/frame/content-type headers, secure cookies, reduced logs or loopback-only API/DB exposure regress |
| Backup | Do not deploy if the fresh local/offsite backup check fails; stop admission if backup age exceeds the approved RPO |

Immediate non-waivable conditions do not wait for a sample size: cross-tenant disclosure,
credential exposure, silent data corruption/loss, unlawful data use and materially false
product claims trigger containment and rollback.

## 14. Approver and decision request

The repository permits one person to sign several or all of the Product,
Engineering/Platform, Security/Privacy and Operations roles for a small pilot, but each
role's decision must still be explicit in this same record. Combining titles does not turn
an untested gate into PASS.

The **independent release reviewer is separate**: they must review the exact `150d118`
diff and evidence, must not be the author/implementer approving their own work, and must
record findings and dispositions. One sufficiently scoped independent review may support
both R04 and S09 only if it actually covers tenancy, authorization, credential handling,
migrations, recovery, concurrency, lineage, product truth and the internet-facing security
threats named by S09.

The import-readiness reviewer is a domain role rather than a release signature. The same
person may also hold another approval role only if they are qualified for the declared
category/jurisdiction and are not the requester for any review they decide. Software role
assignment alone does not establish that qualification.

The remaining named decisions are:

1. **Product/release owner:** name the exact cohort; approve the narrow manual-pilot scope,
   claim inventory, unavailable-feature exclusions, participant notice and whether T03 is
   validly N/A under the constrained T02 pilot.
2. **Independent reviewer:** approve or reject the exact diff with dated findings and
   dispositions; include S09 security scope or name a separate independent security reviewer.
3. **Security/Privacy policy owner:** approve the privacy notice, terms, data inventory,
   Resend/S3 processor treatment, retention/deletion schedule, access/secret ownership and
   incident/data-request process.
4. **Engineering/Platform owner:** approve explicit configuration values, capacity bounds,
   full staging deployment/rollback rehearsal, patch ownership, database privileges and the
   30-hour/4-hour recovery proposal.
5. **Operations owner/on-call:** provide a named destination, support hours, response target,
   observation/change window and alert-injection drill; approve the stop thresholds.
6. **Account-delivery owner (may be Product/Operations):** either finish mailbox-driven
   reset/verification and bounce monitoring under A02, or explicitly disable SMTP and satisfy
   the constrained operator-recovery path A03 before deployment.
7. **Qualified import-review owner:** name the people, Nigerian jurisdiction/product-category
   scope, qualification basis, independence rule and review/expiry cadence, or remove actionable
   review claims from the pilot.
8. **Product + Platform recovery owners:** approve numeric RPO/RTO and retention, and accept
   only after the representative timed restore and deletion-replay evidence meet them.
9. **All four release roles:** record final UTC-dated GO only after every required gate is PASS
   or validly N/A and post-deployment smoke is ready to run before cohort admission.

Approval signatures alone are not sufficient while the technical items marked pending in
sections 7, 9, 12 and 13 remain incomplete.
